# 塔1 金卡自举化 · 修改规格（目标 #2）

> 目标 #2：让金卡（稀有卡）有普遍的、不限本角色的「自举」能力，保证棱镜碎片下其他角色抓取的
> 基本价值。现状均反编译 `desktop-1.0.jar` 核过。cardID = `cards.json` 的 key（塔1 有些带空格）。
>
> **✅ 已实现（2026-07-31）：5 张金卡改造（`patches/`）+ 新增黑暗汇集（§6，`cards/`）+ 删狂乱撕扯，全部加载 0 error；5 张改造已试玩验证。**
> 与本规格文字的实现差异：①光辉用 `baseDamage=3(4)` 巧用原版 `applyPowers`（`baseDamage+=mantraGained`），
> **不** patch applyPowers；②乾坤一掷复用官方 `CalculatedGambleAction(upgraded)` 做弃全抽等量；
> ③雷霆打击的新闪电**已定为不算本次伤害**（默认）。
>
> **不改**：战士 突破极限(Limit Break)、观者 确立基础(Establishment)——本就够用/需配合。
> **要改的 5 张**（角色已核实 color）：

|---|---|---|---|
| 乾坤一掷 | `Unload` | GREEN 静默 | `cards/green/Unload` |

## 通用：改基础卡的 SpirePatch 套路

- **加效果**（在原效果基础上追加）：`@SpirePatch(卡, "use")` 的 **postfix**，`addToBot(...)` 追加 action。
- **改数值**：`@SpirePatch(卡, SpirePatch.CONSTRUCTOR)` postfix 改 `baseDamage`/`baseMagicNumber`；
  升级值改 `@SpirePatch(卡, "upgrade")`（prefix return false 换掉，或 postfix 调整）。
- **改描述**：patch **构造 postfix** 覆盖 `rawDescription`（按 `Settings.language` 给中/英）再
  `initializeDescription()`。升级态描述在 `upgrade()` 里另设。
- 生成充能球：`addToBot(new ChannelAction(new Frost()/new Lightning()/...))`
  （`actions.defect.ChannelAction`）。随机球仿 混沌 Chaos 卡（实现时反编译 `cards/blue/Chaos` 抄）。
- **只有光辉需要跨 mod 去重**（见 §5）；其余 4 张只在本 mod，直接改。

## 1. 乾坤一掷 Unload（静默 GREEN）

**现状**：1 费攻击，`baseDamage=14`，`use`：`DamageAction(14)` + `UnloadAction`（弃掉全部手牌）；
`upgrade`：+4（→18）。**问题**：不是自举问题，是卡本身太差（弃光手牌只换 14 伤）。

**改为**：1 费攻击，**10(11)** 伤，弃掉全部手牌，然后**抽等量的牌（升级 +1）**。

**挂点**：
- 数值：CONSTRUCTOR postfix `baseDamage = 10`；`upgrade` 改为 `upgradeDamage(1)`（→11）。
- 抽牌：`use` postfix —— 弃牌数 = 打出时的 `p.hand.size()`（Unload 已离手，hand 即将被 UnloadAction 弃光）：
  ```java
  int n = p.hand.size();                       // 弃前手牌数 = 会被弃的数量
  addToBot(new DrawCardAction(p, n + (card.upgraded ? 1 : 0)));  // 排在 UnloadAction 之后 → 弃完再抽
  ```
- 描述：`#b10 伤。丢弃你的手牌，抽等量的牌。`（升级 `#b11` + `#b1`）。

**边界**：抽牌数按弃前手牌数固定；若牌堆不够会自动洗弃牌堆。自举价值：棱镜下任何角色都能"过牌+爆发"。

## 2. 偏差认知 Biased Cognition（机器人 BLUE）

**现状**：1 费能力，`use`：+4(5) 集中(FocusPower) + 偏差(BiasPower 1，每回合末 -1 集中)。
**问题**：纯集中卡，非机器人（棱镜下）拿了没充能球、集中无处发力。

**改为**：原效果 + **生成 1 个【冰霜】充能球**（给个即时护盾产出，棱镜下也有基本价值）。

**挂点**：`use` postfix `addToBot(new ChannelAction(new Frost()))`。描述追加 `生成 1 个*冰霜*充能球。`

## 3. 雷霆打击 Thunder Strike（机器人 BLUE）

**现状**：3 费攻击，对全体，每个「本场通道过的闪电球」造 7(9) 伤（数 `orbsChanneledThisCombat`）。
**问题**：没通道过闪电球时 0 伤，非机器人（棱镜下）几乎废。

**改为**：原效果 + **生成 1 个【闪电】充能球**（至少保证打出即有 1 次雷击、且自身能起头）。

**挂点**：`use` postfix `addToBot(new ChannelAction(new Lightning()))`。
⚠️ 时序：原 `use` 按 `orbsChanneledThisCombat` 里的闪电数排伤害。新生成的这颗闪电要不要算进**本次**伤害？
- **算**：postfix 里先 channel、且它会进 `orbsChanneledThisCombat` → 但原 use 已经排完伤害 action 了，postfix 再 channel 不影响本次。若要本次就+1 段，得在原 use 计数**之前** channel（prefix 或 instrument）。
- **默认**：postfix 生成，本次不算、给下次和自举打底（更稳、改动小）。**待你定**是否要本次即 +1 段。
描述追加 `生成 1 个*闪电*充能球。`

## 4. 多重释放 Multi-Cast（机器人 BLUE）

**现状**：X 费，激发最右球 X 次（`MulticastAction`）。
**问题**：没有球时纯废；棱镜下抓到基本无价值。

**改为**：**升级后**额外「生成 1 个随机充能球」（未升级不变；给升级版一个自举起手）。

**挂点**：`use` postfix `if (card.upgraded) addToBot(随机球 ChannelAction)`（随机 orb 仿 Chaos）。
描述升级态追加 `生成 1 个随机充能球。`
> 备注：也可考虑未升级也给（自举更普遍），但计划定为升级才给，先按计划。

## 5. 光辉 Brilliance（观者 PURPLE）—— 重做 + 跨 mod 去重

**现状**：1 费攻击，`baseDamage=12`，`applyPowers`/`calculateCardDamage` 里
`baseDamage += actionManager.mantraGained`（本场累计获得真言数）→ 12(16) + 真言数；`upgrade` +4。

**改为**：1 费攻击（保留），打出时**获得 3(4) 真言**，造成伤害 = **本场获得过的真言总数（含本次获得的 3/4）**，
去掉原来的基础 12 伤。

**挂点**（重做，patch 多个成员）：
- CONSTRUCTOR postfix：`baseDamage = 0`；`magicNumber = baseMagicNumber = 3`（真言获得数，升级 4）。
- `upgrade`：改为 `upgradeMagicNumber(1)`（3→4）；不再 `upgradeDamage`。
- 伤害计算（含本次真言）：`applyPowers`/`calculateCardDamage` postfix ——
  `baseDamage = actionManager.mantraGained + this.magicNumber`（预览就显示「打出后」的伤害，因为打出必获得 magicNumber 真言）。
- `use`（prefix 换掉，或 postfix 追加）：
  ```java
  // 先获得真言，再按「打出后的 mantraGained」造成伤害
  addToBot(new ApplyPowerAction(p, p, new MantraPower(p, card.magicNumber), card.magicNumber));
  int dmg = AbstractDungeon.actionManager.mantraGained + card.magicNumber;  // 打出后总数
  addToBot(new DamageAction(m, new DamageInfo(p, dmg, ...), FIRE));
  ```
  （或做一个"结算时实时读 mantraGained"的伤害 action，二选一，保证与预览一致。）
- 描述：`获得 #b3 真言。造成伤害等于你本场获得过的真言数量。`（升级 `#b4`）。

**⚠️ 跨 mod 去重（作者定：本 mod 优先）**：
- 本 mod（目标 #2）**直接实现光辉重做，零检测负担**。
- 将来目标 #3（观者 mod）里的光辉改动，开头加一句让位即可：
  ```java
  if (com.evacipated.cardcrawl.modthespire.Loader.isModLoaded("CharacterRelicParity_RareInPrism")) return;
  ```
  → 单装任一个都有光辉重做；两个同开只有本 mod 生效，不叠加。
- 目前**只有光辉**需要这套；其余 4 张只在本 mod。

**平衡**：真言引擎攻击卡，与顿悟/灵光/达玛鲁等真言来源联动强；棱镜下其他角色抓到，靠自身获得的
3(4) 真言也有保底伤害，符合"自举"。

## 6. 黑暗汇集 Dark Aggregate（机器人 BLUE，新增）+ 删狂乱撕扯

> 机器人稀有卡偏少，且黑暗球流缺「加速滚值」的手段。**新增**黑暗汇集、**删**狂乱撕扯（主题不符），
> 稀有池 −1+1、更聚焦黑暗球流。✅ 已实现（`relicparity.cards.DarkAggregate`，加载 0 error）。

**新增 · 黑暗汇集**（自定义 `CustomCard`，不是改基础卡）：
- **X 费技能，消耗（升级不消耗）**，机器人 RARE。
- 生成 1 个暗黑充能球；触发所有暗黑充能球被动 X 次（X = 能量）。
- 基本是**漆黑 Darkness 的 X 费化**：`use` = `ChannelAction(new Dark())` + `DarkImpulseAction`×X。
  `DarkImpulseAction`（漆黑升级版用的那个）= 遍历 orbs、对每个 `Dark` 调 `onStartOfTurn()+onEndOfTurn()`
  （滚一次值，含镀金电缆交互）。生成在触发之前，所以新球也被触发 X 次。
- X 费处理照搬多重释放：`int e = energyOnUse!=-1?energyOnUse:EnergyPanel.totalCount; …;
  if(!freeToPlayOnce) p.energy.use(EnergyPanel.totalCount)`。
- 注册：`receiveEditCards`（`EditCardsSubscriber`）里 `BaseMod.addCard` + `UnlockTracker.unlockCard`；
  文案 `CardStrings`（NAME/DESCRIPTION/UPGRADE_DESCRIPTION，中英），卡图占位待换真美术。
- **联动**：一张牌把所有暗黑球滚大 → 激发杀敌 → 坍缩核心保值；愁云惨淡铺球做前置。

**删 · 狂乱撕扯 Rip and Tear**（罕见攻击，7 伤，不碰充能球）：
`BaseMod.removeCard("Rip and Tear", CardColor.BLUE)`。主题不像机器人，删了不影响黑暗球流。

**保留 · 愁云惨淡 Doom and Gloom**（罕见攻击，10 全体 + 生成 1 暗黑球）：它铺暗黑球、帮黑暗球流，
删它反而和本方向矛盾，不动。
